# Zukai Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first slice of Zukai: a Tauri 2 desktop app with Tabs of Text Scratchpads, a CodeMirror 6 editor with a custom find bar, continuous autosave, and Session restore. It uses window layout B with the Paper look, and builds on Windows, macOS and Linux.

**Architecture:** The Rust side owns every file-system operation. Scratchpad files and `session.json` live under `<data_dir>/Zukai/`, and each write is atomic: write a temp file, flush it, then rename it. Rust exposes a small set of Tauri commands. The web side (React + TypeScript) owns all product logic as pure, unit-tested modules: the workspace reducer, Titles, Session (de)serialization, autosave scheduling, shortcuts, language guessing and match counting. A thin React layer wires those modules to CodeMirror views and to the storage commands. Each open Tab gets its own CodeMirror `EditorView`, created the first time the Tab is shown and then kept alive (hidden) so switching is instant and undo survives.

**Tech Stack:** Tauri 2 (Rust); React 19 + TypeScript; Vite; pnpm; Tailwind CSS v4 (`@tailwindcss/vite`); CodeMirror 6 (`@codemirror/view`, `state`, `commands`, `search`, `language`, `lang-*`, `legacy-modes`); Vitest + jsdom + Testing Library; ESLint + Prettier; Clippy + rustfmt; GitHub Actions. Plugins: `tauri-plugin-single-instance`, `tauri-plugin-window-state`. Fonts: `@fontsource-variable/inter`, `@fontsource/jetbrains-mono`.

**Spec:** [`docs/superpowers/specs/2026-10-25-shell-design.md`](../specs/2026-10-25-shell-design.md). Glossary: [`CONTEXT.md`](../../../CONTEXT.md). Read both before starting any task.

## Global Constraints

- Bundle identifier: `io.github.peota.zukai`. Product name: `Zukai`.
- Data folder: `<Tauri data_dir>/Zukai/`, which is `%APPDATA%\Zukai\` on Windows, `~/Library/Application Support/Zukai/` on macOS and `~/.local/share/Zukai/` on Linux. It never follows the bundle identifier.
- Layout: `scratchpads/<id>.txt`, `closed/<id>.txt`, `session.json`.
- Every file write is atomic (temp file in the same folder, then flush, then rename).
- The web UI never touches the file system directly. All file I/O goes through the Rust commands in Task 3.
- Scratchpads are always UTF-8.
- Only one instance runs. A second launch focuses the existing window.
- The OS-native window frame (`decorations: true`) is used, with window title `<Tab title> — Zukai`.
- Recently Closed items expire after 30 days. Empty Scratchpads are deleted on close and never listed.
- An unrenamed Title is the first non-empty line, cut to 30 characters (`…` appended when cut), or `Untitled` when empty.
- No sidebars, toolbars or decorative animation. The only motion allowed is a ≤120 ms fade on floating surfaces.
- Colors are defined only as CSS variables (section 6 of the spec). Tailwind and CodeMirror both read those variables.
- Fonts are bundled, with no network loading: Inter for the UI, JetBrains Mono for the editor.
- Excalidraw must not be added in this slice.
- CI runs on `windows-latest`, `macos-latest` and `ubuntu-22.04`.

## Review Focus

These are the failure modes the spec implies most strongly but no feature test naturally covers. Each line has a pinned test in the task named.

1. **Closing a Tab while an autosave is still pending.** The pending write must be flushed or cancelled before the file moves to `closed/`, and nothing may recreate it afterward in `scratchpads/`. Test in Task 7, `closeFlushesThenStops`.
2. **A failed write (disk full, permission denied).** The original file stays intact, the app keeps the text in memory, shows "Not saved" in the status bar, and retries on the next change. Tests in Task 3 (`atomic_write_failure_keeps_original`) and Task 7 (`writeErrorIsReportedAndRetried`).
3. **A huge single-line paste (5 MB, no newline).** Deriving the Title and guessing the Language must look only at a bounded prefix and stay fast. Tests in Task 5 (`deriveTitleIsBoundedOnHugeInput`) and Task 10 (`guessLooksAtPrefixOnly`).
4. **Emoji or other astral characters where the Title is cut at 30.** The cut must never split a surrogate pair. Test in Task 5, `deriveTitleDoesNotSplitSurrogates`.
5. **Regexes that match the empty string (`^`, `a*`, `\b`).** Counting matches must finish and give sensible numbers, and Enter must still advance. Test in Task 11, `countMatchesHandlesEmptyMatches`.

- Produces, in `title.ts`:

- Produces, in `workspace.ts` (all pure, all returning a new `WorkspaceState`):

  - `newTabState(id: string): TabState` returns the defaults `title: "Untitled"`, `language: "plaintext"`, `wrap: false`, `selection: {anchor: 0, head: 0}`, `scrollTop: 0`, and every flag false.

  ```ts
  const SAVE_DEBOUNCE_MS = 300;
  type SaveStatus = "saved" | "pending" | "error";
  interface Saver {
    schedule(id: string, getContent: () => string): void;   // debounced per id
    flush(id?: string): Promise<void>;                      // one id or all; writes pending now
    stop(id: string): Promise<void>;                        // flush id, then ignore further schedules for it until resume
    resume(id: string): void;
    status(): SaveStatus;                                    // "error" if any id's last write failed
    onStatus(cb: (s: SaveStatus) => void): () => void;
  }
  createSaver(write: (id: string, content: string) => Promise<void>, delayMs = SAVE_DEBOUNCE_MS): Saver
  ```
