# Zukai Files Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Zukai open, autosave, watch and protect real Files on disk. That covers encodings, Disk conflicts, Missing Files, Save As, renaming on disk, the Recently Closed menu, JSON Beautify/Minify and folding, and unsigned installers that register Zukai under "Open with".

**Architecture:**
- **Rust owns every file operation.** It holds an allowlist of granted paths and does the encoding detection and encoding (`encoding_rs`). It checks a fingerprint before every write, watches files (`notify`) and stores shadow files.
- **Paths only enter through Rust:** dialogs, the command line, a second launch, drag and drop, and the Session file. Rust reports them to the web side through one `zukai://open-paths` event, so the webview never invents a path.
- **The web side** extends the existing pure model, with File info on `TabState` and Session v2. A pure `fileState` module decides what to do on disk events, and a document writer routes the existing Saver to the scratchpad, file or shadow store.
- **New UI pieces** sit next to the existing ones: a file bar, status-bar menus, a tab context menu, a JSON formatter and folding.

**Tech Stack:** As in the shell slice: Tauri 2, React 19 + TS, CodeMirror 6, Tailwind v4, Vitest, cargo tests, GitHub Actions. New dependencies:
- Rust: `encoding_rs`, `notify` (with `notify-debouncer-mini`), `tauri-plugin-dialog`, and `xxhash-rust` (feature `xxh3`) for the content hash.
- npm: `@codemirror/language`, which is already present (use its `foldGutter` and `foldKeymap`).

**Spec:** [`docs/superpowers/specs/2026-10-26-files-design.md`](../specs/2026-10-26-files-design.md). Also read [`CONTEXT.md`](../../../CONTEXT.md) and the first slice's plan [`2026-10-25-shell.md`](2026-10-25-shell.md) for the existing modules.

## Global Constraints

- All file I/O happens in Rust. Every File command takes a path that is **granted, absolute and not a folder**, or it is refused with `{ kind: "not_granted" }`.
- Paths are granted only by:
  - the open and save dialogs (shown from Rust)
  - command-line arguments
  - single-instance arguments
  - drag and drop (the Rust window event)
  - File paths in `session.json` that Rust reads at startup
  - rename and Save As results
- `session_write` refuses JSON that references a File path that isn't granted.
- Paths are compared canonically: `dunce::canonicalize`-style resolution, and case-insensitive on Windows and macOS.
- Every write is atomic: a temp file in the same folder, then flush, then rename. Rename-on-disk never replaces an existing file, on any OS.
- **Encoding:**
  - Detection: a BOM (UTF-8, UTF-16 LE/BE) wins. Otherwise valid UTF-8 means UTF-8 with no BOM. Otherwise use the legacy code page: the Windows ANSI code page, or `windows-1252` on macOS and Linux.
  - Files are written back in their own Encoding, BOM and Line ending.
  - New files are UTF-8 with no BOM and the platform Line ending (CRLF on Windows, LF elsewhere).
- **Unreadable as text:** replacement characters on decode, or a NUL byte in UTF-8 or legacy text. The File is read-only and never autosaved.
- **Fingerprint:** `{ mtimeMs: number, size: number, hash: string }`, where `hash` is xxh3-64 of the bytes in hex. Writes are refused when the disk fingerprint differs from the expected one in content.
- **A Tab is "held"** while its File is in `conflict`, `missing`, `unencodable` or `readonly`.
  - Held Tabs never write the File. Their text goes to the shadow file `<data>/Zukai/pending/<tabId>.txt`.
  - For the Saver, a successful shadow write is a successful save.
- Files over **50 MB** are not opened; a notice says "Too large to open yet".
- Session `version: 2`. A v1 file migrates automatically, and every v1 Tab is a Scratchpad.
- **Closed entries:**
  - Closed File entries never expire unless they carry shadow text, in which case the 30-day rule applies.
  - Closing the same path again replaces its older entry.
  - The menu shows the newest 20.
- **Shortcuts** (`Mod` = Ctrl on Windows and Linux, Cmd on macOS; letters by typed key):
  - Mod+O opens files.
  - Mod+S: in a Scratchpad it opens the Save As dialog; in a File it saves now.
  - Mod+Shift+S is Save As.
  - Shift+Alt+F is Beautify JSON.
  - Mod+Shift+[ folds and Mod+Shift+] unfolds.
- **JSON formatting:**
  - It re-indents tokens and never re-serialises values: number text, string escapes, key order and comments are kept.
  - Indent is 2 spaces.
  - Invalid JSON changes nothing and shows "Invalid JSON at line X, col Y".
- **Bars, menus and the badge:**
  - Bar colours are new tokens: `--z-bar-warn-bg/fg` (amber), `--z-bar-err-bg/fg` (soft red) and `--z-bar-info-bg/fg` (chrome grey), each with light and dark values.
  - Menus use `--z-surface`, `--z-radius-float` and `--z-shadow-float`.
  - Floating pieces may fade in for at most 120 ms.
  - A File Tab shows a `FILE` badge.
- **Associated extensions** (stock Tauri `fileAssociations`): `.txt .md .markdown .json .jsonc .log .xml .yaml .yml .ini .toml .conf .cfg .env .sql .js .mjs .cjs .ts .tsx .jsx .css .html .htm .sh .bash .zsh .py .bat .cmd .ps1`. Not `.csv`, `.tsv` or `.excalidraw`.
- **Installers:** NSIS (`installMode: currentUser`), DMG, DEB and AppImage, all unsigned. They are built by a separate workflow on `workflow_dispatch` and on `v*` tags, and uploaded as artifacts.

## Review Focus

1. **Another program saves the File between Zukai's fingerprint check and its rename.** The window is small but real. The write must still be refused when the fingerprint doesn't match at check time. Test in Task 3, `write_refused_when_fingerprint_changed`.
2. **The same file opened twice by different spellings** (`C:\x\A.json` and `c:/x/a.json`, or through a symlink). It must land on one Tab. Tests in Task 4 (`canonical_dedupes_case_on_windows_and_macos`) and Task 8 (`openSamePathTwiceSwitchesToExistingTab`).
3. **Pasted text that contains `\r\n` or a lone `\r` in a CRLF File.** Writing must never produce `\r\r\n`. Test in Task 2, `encode_never_doubles_cr`.
4. **A 5 MB minified JSON pasted and beautified.** Beautify must stay linear and finish in well under a second. Test in Task 6, `beautifyIsLinearOnLargeInput` (5 MB in < 1500 ms, generous for CI).
5. **A watcher event storm** (`git checkout` touching 200 open-or-not files). Zukai must not reload more than once per File per burst, and must not freeze. Test in Task 5 (`debounced_events_coalesce_per_path`), using notify's debouncer with a 200 ms window.

### Task 2: Rust encoding detection and encoding

**Files:**
- Create: `src-tauri/src/files/mod.rs`, `src-tauri/src/files/encoding.rs`
- Modify: `src-tauri/Cargo.toml` (add `encoding_rs`), `src-tauri/src/lib.rs` (`mod files;`)

**Interfaces:**
- Produces:
  ```rust
  #[derive(Serialize, Deserialize, Clone, PartialEq, Debug)] #[serde(rename_all="camelCase")]
  pub struct FileFormat { pub encoding: String /* WHATWG label: "utf-8", "utf-16le", "utf-16be", "windows-1252", … */,
                          pub bom: bool, pub line_ending: LineEnding, pub mixed: bool }
  #[derive(Serialize, Deserialize, Clone, Copy, PartialEq, Debug)] #[serde(rename_all="lowercase")]
  pub enum LineEnding { Lf, Crlf }
  pub struct Decoded { pub text: String /* always "\n" line breaks */, pub format: FileFormat, pub readable: bool }
  pub fn legacy_encoding() -> &'static encoding_rs::Encoding   // Windows: GetACP() → encoding; else WINDOWS_1252
  pub fn detect_and_decode(bytes: &[u8]) -> Decoded
  pub fn decode_as(bytes: &[u8], label: &str) -> Option<Decoded>   // None for an unknown label; readable=false on replacement chars
  pub fn encode(text: &str, format: &FileFormat) -> Result<Vec<u8>, Unencodable>
  #[derive(Serialize, Debug, PartialEq)] pub struct Unencodable { pub ch: String, pub line: u32, pub col: u32 }
  pub fn platform_line_ending() -> LineEnding
  ```
  - `mixed` is true when both CRLF and LF occur. `line_ending` is then the more common one, with ties going to `platform_line_ending()`.

  - `encode` must detect unmappable characters itself: `encoding_rs` would emit `&#NNNN;`. Use `Encoder::encode_from_utf8_without_replacement` and report the first unmappable character with its 1-based line and column.

**Files:**

**Interfaces:**
- Consumes: `storage::atomic::atomic_write` and Task 2's types.
- Produces:
  ```rust
  #[derive(Serialize, Deserialize, Clone, PartialEq, Debug)] #[serde(rename_all="camelCase")]
  pub struct Fingerprint { pub mtime_ms: u64, pub size: u64, pub hash: String }
  pub fn fingerprint_of(path: &Path) -> io::Result<Option<Fingerprint>>          // None if missing
  pub const MAX_OPEN_BYTES: u64 = 50 * 1024 * 1024;
  #[derive(Serialize)] #[serde(rename_all="camelCase")]
  pub struct FileRead { pub text: String, pub format: FileFormat, pub readable: bool, pub fingerprint: Fingerprint }
  pub fn read_file(path: &Path) -> Result<FileRead, FileError>                    // FileError::TooLarge over MAX_OPEN_BYTES
  pub fn reread_as(path: &Path, label: &str) -> Result<FileRead, FileError>
  #[derive(Serialize)] #[serde(tag="kind", rename_all="camelCase")]
  pub enum WriteOutcome { Written { fingerprint: Fingerprint }, Conflict { fingerprint: Fingerprint }, Missing, Unencodable { ch: String, line: u32, col: u32 } }
  pub fn write_file(path: &Path, text: &str, format: &FileFormat, expected: &Fingerprint) -> Result<WriteOutcome, FileError>
  pub fn save_as(path: &Path, text: &str, format: &FileFormat) -> Result<WriteOutcome, FileError>   // no fingerprint check
  pub fn rename_no_replace(from: &Path, new_stem: &str) -> Result<PathBuf, FileError>   // keeps extension; FileError::Exists
  // storage/shadow.rs
  pub fn write(base: &Path, id: &str, text: &str) -> Result<()>; pub fn read(base, id) -> Result<Option<String>>;
  pub fn delete(base, id) -> Result<()>; pub fn list(base) -> Result<Vec<String>>
  ```
  - `FileError` serializes as `{ kind, message }`, with `kind` one of `"io"`, `"not_granted"`, `"not_a_file"`, `"too_large"`, `"exists"`, `"invalid_name"`.
  - **`write_file`:**
    - If the current fingerprint is `None`, the outcome is `Missing`.
    - If the size or mtime differs from `expected`, it re-hashes. A different hash means `Conflict` with the disk fingerprint.
    - Unencodable text gives `Unencodable`.
    - Otherwise it does the atomic write, keeping Unix permission bits from the original, and returns `Written` with the new fingerprint.
  - **`rename_no_replace`:** Windows uses `MoveFileExW` without `MOVEFILE_REPLACE_EXISTING`. Linux uses `renameat2(RENAME_NOREPLACE)`, falling back to `link` + `unlink`. macOS uses `renamex_np(RENAME_EXCL)`. A stem containing path separators or reserved names gives `InvalidName`.

- Watch the **parent folder non-recursively** and filter to the watched files. Many editors save by delete-and-rename, so watching the file itself loses it.
- Debounce with a 200 ms window and coalesce per path.
