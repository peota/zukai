# Split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two Tabs joined into one tab in the single tab bar, shown side by side or top and bottom, made from a tab's menu, Mod+\\ or by dragging a tab onto the editor's edge.

**Architecture:** `WorkspaceState` gains optional `splits`. `activeId` stays the focused half's Tab, so commands, the status bar and Settings need no changes. Pure functions in a new `model/split.ts` keep the rules, and the existing workspace functions call them. The layout moves from `App.tsx` into a per-Tab `TabPane` and a two-pane `SplitView`. `EditorHost` learns to show two views at once in elements App gives it.

**Tech Stack:** React 19 + TypeScript, CodeMirror 6, `@excalidraw/excalidraw` 0.18.1, Vitest + Testing Library (jsdom). There's no Rust change.

**Spec:** `docs/superpowers/specs/2026-11-19-split-design.md`

## Global Constraints

- **Glossary:** a Split is exactly two Tabs, shown as one joined tab in the single tab bar. There's no second tab bar and no nesting. Don't use the words pane or editor group in UI copy.
- **Orientation:** `orientation: "row" | "column"`. "row" (side by side) is the default; "column" is top and bottom.
- **Ratio:** within 20–80%. Reuse `clampSplit` from `src/model/settings.ts`. A new Split starts at 0.5, and double-clicking the divider resets it to 0.5.
- **One Split per Tab:** a Tab is in at most one Split, and the two members are different Tabs.
- **Members stay together:** they're always next to each other in `tabs` (a, then b), and they share the pin.
- **activeId:** a Split's focused member is always `activeId` while the Split is shown.
- **Menu copy, verbatim:**
  - `Split with` (submenu)
  - `Unsplit`
  - `Swap sides`
  - `Side by side`
  - `Top and bottom`
  - `Close split`
- **Shortcut:** `Mod+\` matches `e.code === "Backslash"` or `e.key === "\\"`.
- **Session:** older Sessions have no `splits` and load with none.
- **Libraries:** no new dependencies.

## Review Focus

1. **Find in a Split.** Mod+F in a Split must open the find bar over the focused half, never the other half or the hidden editor container. Task 3 adds `findBarSitsInTheFocusedSlot`.
2. **Two canvases in one Split.** Typing or a shortcut in one canvas must not reach the other Excalidraw. Task 4 adds `excalidrawHandlesKeysLocally`, which pins `handleKeyboardGlobally={false}`.
3. **Focus moving into a Split some other way.** Ctrl+Tab, Mod+1–9 or a sidebar click can land on a member. That member must become the Split's focused half, so reselecting the joined tab returns there. Task 1 adds `activatingAMemberFocusesIt`.
4. **Two text halves.** Typing in one half must change only its own document and undo. Unsplitting must keep both histories, with nothing recreated. Task 3 adds `twoViewsKeepTheirOwnUndo`.
5. **A Session whose Split is broken.** A member that's gone, a Tab listed twice, or members saved apart must load as ordinary or reunited Tabs, never crash or lose a Tab. Task 1 adds `normalizeDropsAndReunites`.

- Test: `src/model/workspace.test.ts`, `src/model/session.test.ts`

**Interfaces:**
- Produces:
  - `type SplitOrientation = "row" | "column"`
  - `interface Split { a: string; b: string; orientation: SplitOrientation; ratio: number; focus: "a" | "b" }`
  - `WorkspaceState.splits?: Split[]`
  - in `model/split.ts`:
    - `splitOf(s, id): Split | undefined` (id is either member)
    - `otherHalf(sp: Split, id: string): string`
    - `makeSplit(s, a, b, orientation?: SplitOrientation): WorkspaceState`
    - `unsplit(s, id): WorkspaceState`
    - `swapSides(s, id): WorkspaceState`
    - `setOrientation(s, id, o: SplitOrientation): WorkspaceState`
    - `setSplitRatio(s, id, r: number): WorkspaceState`
    - `normalizeSplits(s): WorkspaceState`
- `makeSplit` puts b right after a and gives b a's pin. Focus goes to whichever member was `activeId`, else a, and `activeId` becomes that member. It returns `s` unchanged if a === b, either id isn't an open Tab, or either is already in a Split.
- `normalizeSplits` drops Splits whose member is missing, repeated or the same as the other. It moves b next to a and shares a's pin with b. Every workspace function that changes `tabs` returns its result through it.

  - **`activatingAMemberFocusesIt`:** `activate(s, "b")` on a Split sets focus "b"; activating "a" again sets "a".

    - a Split repeating a Tab already in another Split is dropped
